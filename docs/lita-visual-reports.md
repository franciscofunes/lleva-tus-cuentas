# LTC host support for Lita visual reports

Lita now builds accurate local Canvas PNG reports from the preexisting authenticated, bounded `lita:forecast:request` contract. There is no new expense query and no Firestore write. In Banks, Lita uses `monthlyCardSpending.byCurrency` historical statement aggregates, not individual PDF purchases.

## Opt-in runonweb decorative image

The iframe can send `lita:illustration:request` with **only** a random requestId. The host validates exact iframe source + origin, authenticated user, allowed section (Transactions/Banks), requestId syntax and visible financial values. It dynamically imports `localLitaIllustration` which invokes `runonweb/image` with a **constant generic abstract artwork prompt** (no monetary amounts or user data).

`scripts/build-browser-ocr.cjs` emits an additional image-model ESM entry, without shipping its code or model weights into initial LTC/OCR bundles. The image is generated on the user's GPU with Bonsai Image 4B binary (~3.4 GB first-time download); unsupported WebGPU and devices exposing <8 GB device memory are refused. A progress event returns only requestId and integer progress; the result is a generated PNG Blob, which Lita composites into the Canvas report. Never transfer raw images, financial values or prompts from Lita to the model.

Normal deterministic reporting does NOT depend on WebGPU or runonweb. No custom AI credentials, remote image API or new Firestore collection is needed.

## QA

Run the browser suite including `src/utils/localLitaIllustration.test.js` and production build. CI tests the model integration with a virtual mock only; actual weights/GPU runtime require manual desktop smoke test. Maintain exact postMessage origin/source guards. Roll out the host before Lita.


## Local image model: compatibility and diagnosis

Bonsai Image 4B runs in-browser on WebGPU only (no WASM fallback). The installed `runonweb@0.1.0` SDK loads a ~3.4 GB binary checkpoint on first use via `ImageGenerator.load()`, then `generate()`, then `dispose()`. Images stay decorative; real financial numbers and charts are rendered deterministically with Canvas.

Before attempting a download LTC now runs **on-device** `checkLitaLocalIllustrationCapability()`: verifies `navigator.gpu.requestAdapter()`, and refuses the model when the browser estimates less than 8 GB memory. This 8 GB heuristic is a deliberately conservative guard, not a guarantee of model compatibility or a vendor minimum. Browsers may report capped approximate RAM. A compatible result still can fail from GPU memory or insufficient storage. No hardware identifier is transmitted to the server.

The trusted iframe bridge adds `lita:illustration:capability:request/result` (random bounded request ID plus supported/reason, no user details). The existing generation result carries sanitized failure reasons instead of a silent null. Lita should disable the model button when unsupported and link to the official self-test: https://runonweb.ai/models/image. There is no remote image-generation fallback.

Use Chrome/Edge with WebGPU on a computer with sufficient GPU/storage, preferably Wi-Fi. A phone browser that reports less than 8 GB cannot use this opt-in in LTC; the regular PNG continues to work. Do not tell the user that a PNG with charts was generated by an AI model.

Review changes to SDK or bundled model before relaxing the guard. Full weight download and inference are not exercised in CI.


## Post-preflight GPU error phases

`checkLitaLocalIllustrationCapability()` confirms only preliminary WebGPU adapter/memory compatibility. On some phones, loading Bonsai Image 4B still fails (model binaries ~3.4 GB, GPU/device memory constraints), even when preflight is green.

The generation helper now tags failure phases `runtime` (loading browser runtime), `weights` (downloading/loading the large model), `generating` (GPU inference), and `validation` (PNG output). `lita:illustration:progress` includes a whitelisted `stage`, and `lita:illustration:result.reason` contains a safe, stage-specific explanation. Never forward raw SDK URLs or financial data. Lita can present a separate procedural **Canvas (sin IA)** option on unsupported devices; this is not a cloud or AI image.

Unit tests verify the stage-specific errors and bounded iframe payload. Full GPU generation cannot be established in CI.
